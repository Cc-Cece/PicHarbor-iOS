# 0.2.5 新拍照片与重试修复

## 真机反馈与定位

用户确认：Motion Photo 双条目按格式特性接受；原始配对联合提交表现最好。旧照片两种原始配对通常一次完成，新拍几分钟内的照片偶发资源数为 0、SOURCE_CHANGED，继续重试无效，重新选择备份有效。先照片后视频偶发静态显示或需多次确认。

代码定位：创建时冻结 PhotoKit 版本，准备导出前严格比较；旧重试不刷新版本。资源数为 0 的准备失败发生在上传前，不能据此推断云端关联失败。尚未取得具体变化字段或相机处理时序证据。

## 本轮行为

- 所有未导出任务在准备阶段重新读取当前 PhotoKit 资产，连续三次（间隔一秒）检查版本和资源类型、UTI、原名组成的清单；单次最多六次观察。
- 稳定后仅允许无导出源、无上传资源、无配对记录及核验证据的任务更新版本、Live 类型和拍摄/修改日期，保持任务 ID、账号、画质、版本策略、来源与批次。
- 导出后再读取版本及清单。不一致时丢弃本任务尚未上传的准备目录，等待后重新导出，避免混合照片与视频版本。
- 连续变化最多自动等待六轮，随后显示需处理；继续／重试会重新开始稳定检查。0.2.4 遗留的无资源 SOURCE_CHANGED 任务也可直接继续，无需重新选照片。
- 相册稳定等待单独计数，不消耗网络失败的重试预算；暂停或断网保持原有可操作状态。
- 同一账号、资产与内容策略已有准备/等待任务时，不随新版本通知重复创建准备任务。
- 已导出、传输、提交的版本不被自动替换；配对不明继续只查询，不解除提交保护。错误提示区分相册准备、暂存文件变化和云端关联等待。
- 三种策略和默认值保留。没有将单纯的静态原图可见判为完整 Live Photo，没有开放 Live Photo 清理。

稳定观察是防抖；不能保证照片以后永不变化。导出后的检查及已上传版本冻结共同保证任务绑定正确。检查清单不会写入诊断，避免泄露原名。

## 验收

自动回归包括：版本变化后重新计数、资源清单变化、连续变化退出、暂停/权限/网络中止、未导出任务刷新及持久化、已导出/已提交版本禁止刷新，及既有配对提交保护。

真机仍需验证：

1. 直接继续旧的资源数 0、SOURCE_CHANGED 任务，确认不再要求重新选照片。
2. 拍摄后立即分别以联合提交、先照片后视频备份；等待期间不重新创建任务，观察自动推进。
3. 准备期间编辑照片、暂停、切换网络或终止重开，确认无混合资源及错误完成。
4. 先照片后视频若仍仅静态，记录任务是否已完成、错误码及实际关联路径，分别检查等待中与最终完成后的表现。云端协议效果没有因本轮本地修复而视为已解决。
