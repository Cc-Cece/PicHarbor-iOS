## 本轮行为

- 网络偏好应用于当前账号所有未完成任务，暂停保持暂停。停止旧策略的系统传输后从文件边界重建，保留已提交或已确认的资源与响应；不修改画质、Live Photo 或编辑版本策略。恢复应用及切换账号后也协调网络策略。
- 活动默认按批次，菜单可改按手动/自动或不分组。每次多选或一次自动扫描为一批；重新准备继承已知来源和批次，旧记录明确标记未知。
- 左滑、详情或菜单按当前筛选移除未完成任务，需要确认。取消导出及系统任务，仅清理不再使用的暂存文件。保留内部取消标记和媒体身份，防止旧回调复活及自动扫描立刻重建同一版本；手动可重新备份。不删除本机或云端媒体，不移除已完成记录。
- 文件哈希存在确认与动态处理确认分开显示。最终确认使用哈希查重返回的规范资源标识；提交后失效旧图库缓存。动态确认按固定 gpmc 的可选字段语义处理缺失回收站标记，清理仍保留更强的显式证据要求。输出索引未出现、处理中、尚无动态标记、回收站状态未知或已删除等具体原因，退避继续检查，提供立即重新确认入口。
- 原名与封装名不参与最终确认比较。Motion Photo 改变文件内容，官方客户端同时显示本机原件和云端封装项不能单凭文件名解释，也不能通过改名保证合并。应用不删除云端项目来掩盖两份显示。

## 复测

1. 保留原 Sideloadly 配置覆盖安装，保留旧 Live 任务，不要重新准备或重新上传。进入详情“立即重新确认云端”，核对最终状态；若仍等待，记录需要处理区域的具体原因/脱敏错误码。
2. Wi-Fi 限制下建立任务，允许蜂窝后观察原任务继续；再限制 Wi-Fi，检查蜂窝下等待。暂停任务切换设置后应保持暂停，手动继续后采用新网络条件。传输重建可能重新发送当前文件。
3. 多选创建一批、再创建另一批，开启自动备份发现新项目，检查三种分组；旧任务保持未知分类。
4. 单项和筛选批量移除失败、等待、暂停及运行中任务，确认已完成记录保留、原始照片和云端项目保留、重启不复活、自动扫描不立即重建；同一项目仍可手动备份并先查重。

自动检查及最终 IPA 记录见 DEVELOPMENT-ACCEPTANCE.md；真机确认修复效果仍待用户复测。
