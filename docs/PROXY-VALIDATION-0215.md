# 0.2.15 · 应用内代理验证版

基于用户已提交的 `579ad2c`，在 `proxy-validation-0215` 独立分支制作，不覆盖主工作区。应用锁及系统 VPN 不在范围内。

## 实现与边界

- 使用 ProjectClash Apple SDK `v1.19.32-clash.3`，下载归档 SHA-256 `fbee3cf05b24de4e1b35d0f87f3510832a05ab04d7e3226494126527acadb756`。构建脚本验证 SDK、来源清单和第三方许可摘要，仅链接 iOS 设备/模拟器切片，静态 SDK 不额外嵌入 framework。不需要 Network Extension、App Groups 或 VPN entitlement。
- 核心以非 Network Extension 平台启动，拒绝 OpenTun；监听 `127.0.0.1:24500–24563`，每节点独立入口绑定明确出口。导入的 TUN、系统路由、规则、控制接口及 DIRECT 不进入实际配置，未匹配流量为 REJECT。
- 首版支持最多 64 个 `proxies` 节点的 Clash YAML/JSON，及返回这种配置的 HTTPS 订阅；不支持 `proxy-providers`、代理链、外部规则。导入先解析和启动校验，节点数据仅保存在本机独立 Keychain 服务；订阅 URL 不持久化或发往转换服务。首次订阅下载需要所选网络可达。
- 设置 → 应用内代理（验证）：导入、首选节点、最多 8 个有序备用节点、全局兜底和 Google 连通性测试。默认关闭代理，默认代理失败等待。更改核心配置或开关前需暂停活动任务。
- 任务 → 任务连接策略：默认跟随全局，也可单独选择等待、备用节点、备用节点后直连，随任务保存且不覆盖全局。实际请求绑定 TaskLocal 路线并在 Python JSON 桥接中显式传递；两任务不通过修改共享节点互相影响。
- 网页登录使用 WebKit 公共代理接口；Python 每次调用使用显式本机代理，关闭环境变量代理继承，继续验证 Google HTTPS 证书；原生代理上传使用隔离的文件上传会话。不同会话的任务编号命名空间隔离，避免回执和暂存文件混用。
- 非代理上传沿用系统后台会话。代理上传使用前台会话，iOS 暂停/终止时不保证持续传输；恢复后核对持久化任务并重新连接。策略变化从文件边界重试，已提交内容继续先查询，避免重复提交。
- 登录失败、文件错误等不触发自动切换。连通性失败按许可尝试备用或直连；未允许直连时不会自动直连。直连不可达同样等待，不标记完成。

## 用户验证

1. 用相同 Sideloadly 账号与 bundle ID 覆盖安装，保留凭据和任务。默认代理关闭。
2. 设置 → 应用内代理（验证）→ 导入含 `proxies` 的 Clash YAML；选择首选节点和备用节点。
3. 开启代理，关闭第三方 VPN，点击测试。无系统 VPN 授权；通过表示 Google 测试地址可访问，不代表账号认证已通过。
4. 保持前台，测试 Google 登录/已有账号确认、普通照片、视频及原始配对 Live Photo 上传。
5. 同时创建两个任务，在各自连接策略选择不同兜底。断开主节点，观察等待/备用/直连仅影响对应任务。
6. 暂停、继续、切 Wi-Fi/蜂窝、锁屏后返回、终止后重开，验证任务不错误完成、不丢失、不重复提交。
