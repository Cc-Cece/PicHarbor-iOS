# 任务重试与超时保护 · 0.2.27

## 默认设置与入口

“设置 → 备份偏好 → 高级配置”新增“自定义任务保护”。关闭自定义时仍使用内置保护；开启后可输入整数并应用。与并发模式独立，按账号保存。恢复自动管理会同时恢复内置并发与任务保护；恢复备份默认配置也会清除自定义保护。

| 项目 | 内置默认 | 可设置范围 |
|---|---|---|
| 自动重试次数 | 3 次，首次执行之外最多再试 3 次 | 0–10 |
| 上传检查／云端查询阶段 | 60 秒 | 15–300 秒 |
| 保存／配对提交阶段 | 90 秒 | 15–600 秒 |
| 准备或传输无进展 | 120 秒 | 30–1800 秒 |
| 文件处理总上限 | 120 分钟 | 10–1440 分钟 |
| 云端待处理累计等待 | 60 分钟 | 10–240 分钟 |

新设置用于随后开始的执行轮次；正在运行的阶段或传输保留该轮策略。文件上传的有效总时限按 `min(总上限, max(10 分钟, 5 分钟 + 文件字节 / 64 KiB/s))` 计算，兼容 64 位大文件；准备阶段不知道实际资源大小时使用文件处理总上限，同时检查无进展。

这是重试次数与时间的双重上限：先达到任一上限就停止自动推进，不保证一定会用完全部重试次数。网络错误、代理异常、请求超时及无进展超时使用同一有限预算，开启应用内代理不会绕过重试限制。权限、认证、资源损坏等仍按对应错误要求人工处理，不盲目自动重试。

## 实际进展与等待

- 只在资源准备完成、首次取得上传响应、提交检查点、云端键及完整确认等新持久化里程碑出现时补充预算。阶段名、数据库版本号、更新时间、重复取得同一响应均不算新进展。
- 同一检查点连续有效执行无进展达到设定秒数，或没有进展却发生 32 次阶段交接，转“需处理”，避免阶段循环反复重置计时器。
- 云端“尚未就绪”属于正常等待，不按网络失败累计重试次数；累计等待仍受单独上限约束。等待重试的任务不占工作名额。文件上传不会沿用旧云端等待提示消耗云端等待预算。
- 暂停、等待 Wi-Fi、断网以及观察到的进程挂起间隔不消耗调度器有效执行时间。系统中断底层连接仍可能产生网络错误，按网络状态决定等待或有限重试。
- 预算与已见里程碑持久化，普通重启或切换阶段不重置。云端等待和传输计时最多约一分钟未落盘；重启可能少计这段时间，不会多计停机时间。
- 手动“继续／重试”明确开启新一轮预算，保留资源、上传响应和提交屏障，不重新导入照片。诊断及任务高级信息保留原始错误码、自动失败次数、累计无进展时间和交接次数。

## 取消与一致性

Python 请求拥有独立的总时限和取消标识。Requests 的 HTTP／HTTPS 连接和本机 HTTP 代理连接都绑定到该请求的 socket；超时会关闭它们，不依赖服务器持续少量回包来重置读取超时。不会使用全局 monkey patch、强行向 Python 线程注入异常或关闭 TLS 校验。协议分页循环也检查预算。

Swift 阶段看门狗可取消该轮 Python 请求、PhotoKit 下载、流式哈希及封装。哈希与封装在分块边界退出；不能安全中断的系统同步调用仍须返回后退出，不能通过修改卡片状态制造虚假的空闲线程。工作名额在执行器实际退出后释放。代理启动和探测的等待者可独立超时，迟到结果不写入任务；无法停止的第三方共享选路操作最多保留 32 个等待者，防止无限新增。

PhotoKit 导出取消时先关闭本次文件并结束等待，再通知系统取消请求。文件结束操作只执行一次，迟到的数据和完成回调不能再次写入、删除同路径的新文件或重复唤醒等待者；不要求系统完成回调及时到达才释放准备名额。

URLSession 传输无进展或累计时限到达后，先持久化解除旧传输 ID 并安排有限重试，再取消对应系统任务。旧回执不能覆盖后续任务进度。请求采用无进展超时；后台上传的实际调度、系统调用中止时机仍由 iOS 决定，调度器额外累计限制在应用可运行时检查，不承诺挂起时运行应用看门狗。

协议请求超时和传输无进展会反馈给现有代理节点健康与切换策略；是否切换仍遵循用户选择，不隐式允许直连。文件总时限耗尽可能只是大文件传输较慢，不据此判定节点故障；认证错误也不计为节点故障。

提交／配对超时并不代表服务器没有收到请求。保留已提交屏障，后续仅查询保存或关联结果，不清除标记来强行重新提交。达到任何保护上限都不会将任务标为已完成，也不会删除本机或云端照片。

## 验证

Python 测试使用真实本机 HTTP 服务模拟无响应头、持续少量返回数据、独立请求取消、HTTP 代理、HTTPS 包装 socket、取消与注册竞态、挂起观察间隔及桥接错误回包。HTTPS 测试只在临时目录生成自签证书，并仅为该测试连接指定信任；正式应用继续使用证书校验。测试不访问用户代理订阅或账号。

原生核心回归覆盖重试耗尽与重启持久化、阶段变化不重置、重复上传响应不补充预算、交接循环、执行看门狗、进度与挂起区分、独立选路超时及迟到结果、大小相关传输时限、参数范围、提交屏障和旧提示不干扰文件上传。使用正式导出写入器和真实临时文件测试并发数据写入、取消、迟到数据及完成回调；测试不读取系统图库。真实断网、后台／锁屏、大文件、代理故障和 Google 提交结果仍需 iPhone 验收。

## 现有恢复入口的边界

0.2.27 的任务保护本身不会修复缺失的暂存文件。暂存原件是沙盒磁盘文件，路径不存在不能单独证明相册原件丢失，也不能区分实际文件被清理与旧沙盒绝对路径失效。

0.2.28 已增加[统一重试与暂存恢复](TASK-RECOVERY.md)，在原任务内修复路径或重新导出，旧版“取消并另建任务”的普通入口已移除；提交结果不明确时仍保留查询屏障。
