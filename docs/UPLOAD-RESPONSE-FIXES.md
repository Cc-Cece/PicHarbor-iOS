# 0.2.2 上传响应文件与重试修复

日期：2026-10-19。

## 真机反馈与证据边界

0.2.1（构建 3），用户 iOS 27.2；应用能预览照片，诊断显示运行环境、钥匙串和任务库均就绪。114 个任务：1 完成、38 失败、75 暂停；错误以 FILE_ACCESS 为主，另有 REMOTE_NOT_VISIBLE。原诊断未记录失败阶段，不能仅凭这些字段证明全部失败都来自同一处，也不能证明“完成”的一项一定经过了实际传输（可能是云端已有内容）。

代码确认存在的问题：响应文件只在响应头回调中创建，数据回调直接打开它；重启/回调次序变化时没有兜底创建。完成回调也未验证响应文件存在且非空。随后读取响应文件的错误被归为 FILE_ACCESS，且提交标识已提前设为 true，可能使后续重试一直查询尚未提交的内容。

## 修复

- 响应数据回调可独立创建文件；准备操作不截断已收到的响应，跨实例读取仍保留数据。限制响应最大 4 MiB，写入错误保留具体代码。
- HTTP 成功后必须确认响应文件存在且非空；缺失、空、过大或读写失败不会进入云端提交。
- Python 在调用 gpmc 提交 RPC 前验证路径边界、大小和 protobuf；失败返回明确的 UPLOAD_RESPONSE_*。允许暂存目录的合法符号链接别名，仍拒绝越界。
- 只有明确发生在提交 RPC 之前的响应错误，才能撤销对应资源的提交标识；网络不明错误、旧版 FILE_ACCESS 和其他资源的标识保持不变，继续先查云端。
- 记录失败阶段和脱敏的系统错误域/数字码，不记录路径、照片、完整文件名、账号或凭据。
- 任务详情提供“重新准备此任务”：保留旧任务为已取消，保持原任务设置，重新读取相册并先查重。不会删除本地相册或云端内容。普通任务不强制重传已查到的内容；原任务若为用户主动选择的强制重新备份，则保留原有选择，确认框明确说明。

## 验证与真机复测

新增模拟器 PhotoKit 实际资源导出和再次哈希、无响应头时分块落盘、重复准备和跨实例保留、空/缺失响应拒绝、提交标识安全边界测试；Python 检查失败时提交 RPC 调用数必须为零。构建和最终测试结果见 DEVELOPMENT-ACCEPTANCE.md。

升级后先保留暂停任务，选择一个旧 FILE_ACCESS 失败任务，执行“重新准备此任务 → 重新读取原件并查重”。观察新任务是否完成并在 Google Photos 核对。成功后再继续其他任务；如失败，任务详情会显示具体步骤和更精确错误，导出新版诊断供进一步定位。旧的暂停任务不会因升级自动开始，也不要求重新导入照片或卸载应用。

自动测试不使用真实账号，不能替代用户在 Google Photos 上的实际提交验收。Live Photo 及后台等既有剩余验收范围不变。
