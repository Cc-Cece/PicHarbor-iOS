# 0.2.14 · 分享与重复备份

版本 0.2.14 / 构建 16。

- 分享方案修订：用户真机反馈单项 Live Photo 分享提示无法分享，现按用户决定恢复为照片＋配对视频两个文件，通过系统菜单分享。移除未通过验收的单项表示代码及对应实验测试，不再把该方案列为支持能力。
- 首次点击 Live Photo 分享时提示：“此处会将照片和配对视频作为两个文件分享。如需分享为一张动态照片，请前往 iPhone 自带的‘照片’应用。”按钮为“继续分享／取消”。只有点击继续才在本机记录已提示，取消后下次仍提示；确认后不再重复显示，不随账号切换重置。普通照片、视频直接分享。
- 手动再次备份允许创建检查任务；自动备份继续抑制相同版本，避免扫描循环无限生成任务。
- 查重比较内容哈希及大小，不比较文件名；当前账号历史已确认记录（包含归档记录）用于保护重复备份。已有成功证据却暂未云端命中时，先有限退避重查，再进入需处理状态；不直接重新上传。
- 普通照片复用云端哈希查询结果，原始 Live Photo 仍要求照片与动态视频指向同一云端项目。全部复用后显示“已存在，跳过”，混合任务保留“已备份”。旧任务的强制上传标记不再绕过查重。
- 查询持续未命中时，可由用户在 Google 相册确认后选择“仍要重新上传”；二次确认后仍执行查重，仅在未命中时允许上传，并提示重复风险。
- 活动菜单分组、配齐图标，采用“暂停任务／继续任务”“选择归档／归档已完成”“已归档”“移除未完成”等短标题，作用范围仍为当前筛选或当前批次。
- 旧版备份记录移入归档页“旧版记录”，不删除数据，不伪造关联到本机照片的新任务。

保留 0.2.13 的界面合并、详情、归档设置、10 秒通知及释放空间入口调整。真机重点：同一未编辑资产再次备份是否在查重后结束、暂时查询失败时是否避免重传，以及分开分享时照片与视频是否完整。若需要以一张 Live Photo 分享，使用苹果自带相册。

本次分享回退及首次提示仅修改本地，按用户要求不提交、不推送、不触发编译。现有 IPA 不包含这次回退。此前未提交的其他修改保留。
