# 上传速度与剩余大小

## 0.2.24：剩余大小替代预计时间

备份卡片改为“当前速度”“剩余大小”，移除预计时间与按平均照片大小推算的逻辑。

- 剩余大小使用真实资源字节，减去已发送部分；照片、视频及 Live Photo 配对资源合计。
- 仍有未准备完成的项目时，显示“至少 X MB”和“另有 N 项待计算大小”；暂时没有已知字节时显示“计算中…”。不会将部分已知大小当成整个队列的准确总量。
- 所有大小已知后显示实际剩余值。暂停、断网或等待 Wi-Fi 不影响显示已知剩余字节；仍沿用当前账号待推进队列范围，不包含已完成、已移除、暂停或需手动处理的任务。
- 上传字节归零后显示 `0 KB`，提示“等待确认保存”；不会据此将任务标记为已备份。
- 当前速度、缓存、账号隔离及上传流程不变，三种界面语言同步更新。已有原生回归改为检查实际字节、未知数量、离线显示及大于 4 GiB 的大小。

以下保留 0.2.23 的历史说明与验收记录，其中预计时间已被本轮替换。

## 0.2.23 历史行为

备份页“备份进行中”卡片增加“当前速度”“预计时间”，支持简体中文、English、粵語（香港）。

- 速度使用 URLSession 实际发送字节及系统运行时钟，合并所有并行上传，显示约 8 秒移动平均。界面每秒更新，数据不足时显示“计算中…”，没有传输或网络不可用时显示零速率。
- 单独识别系统传输及照片／视频资源。切换文件不叠加各文件的平均速度；计数回退、旧回调、长时间挂起后恢复不制造突增。账号变化清空统计，初次恢复已发送一部分的任务以当前计数作为基线。
- 预计时间面向当前账号仍待推进的上传队列，按剩余字节与当前速度估算。未准备的照片仅参考相同媒体类型和备份方式的已知大小；没有对应样本时保持“计算中…”。暂停、失败和需手动处理的任务不加入倒计时。
- 已确认、已有上传响应或已提交的资源不重复计算上传量；Live Photo 照片和视频分别统计，视频使用 64 位字节数。
- 所有上传量已发出时显示“等待确认保存”，不将其变成已备份。云端动态处理时间不包含在速率推算中，界面明确标注“预计时间仅供参考，照片准备和云端处理可能需要更久”。
- 不为获取大小额外导出或下载原件，不读取私有 PhotoKit 属性，不额外扫描数据库。队列大小统计在任务变化时缓存；进度回调不重新遍历整个图库或触发活动重新排序。
- 统计只在内存中使用，不写入业务数据库，不改变上传并发、调度、查重或确认标准。

独立原生测试覆盖并行／连续小文件、计数回退、旧回调、后台恢复、账号与暂停任务隔离、未知视频大小、大于 4 GiB 的文件，以及云端确认与传输时间分离。UI 显示及实际网络下的估算波动仍需真机验收。
