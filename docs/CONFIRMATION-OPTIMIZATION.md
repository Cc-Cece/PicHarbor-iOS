# 0.2.6 配对蓝色状态与云端确认优化

## 状态语义

- 原始配对任务的每个版本中，照片 SHA-1 与动态视频 SHA-1 已经查询到同一非空云端标识，完整资源集合与配对记录一致时，进入持久化 `paired` 状态。
- 活动列表、任务详情及照片网格显示蓝色对勾：“即将完成 · 配对已确认”。详情明确标明仍待最终核验。
- 最终动态标记、处理状态、回收站状态及可选相簿同步通过后，才进入绿色 `completed`。蓝色状态保留暂停、取消、移除未完成任务与立即重新确认入口；不计入已备份数量、不进入清理候选。Live Photo 清理总体仍关闭。
- Motion Photo 没有原始照片/视频双哈希配对证据，不授予原始配对蓝色状态。
- 重启及升级后，对已保存完整配对证据、仍未完成的活动任务恢复蓝色状态，不重传文件。暂停和错误状态仍按实际条件展示。

## 查询与调度

- Python 协议首次建立完整图库快照，随后在同一账号会话内保留同步令牌和快照，增量读取变更、分页及删除。上传提交使缓存过期，但保留增量游标，避免每次重新扫描整个图库。
- 增量失败时，不发布部分证据，清空快照及令牌；下次查询从完整同步恢复。账号切换创建新的协议对象，不共享快照。
- 确认缓存由同账号任务共用，保留 15 秒。待确认重试按 5、10、20、30 秒逐步退避，封顶 30 秒；调度定时器约 10 秒，实际时刻还受网络、系统执行和协议队列影响。
- 确认等待单独计数，不耗尽网络重试预算。已完成配对的任务不再每轮重复执行两次哈希查询；仍要求最终云端动态证据，不跳过检查。
- 原有两个上传名额之外另设一个最终确认名额；等待中的确认任务不占上传名额。后台文件传输仍由系统管理；Python 协议调用仍串行，初次完整同步仍可能影响其他协议请求。
- 尚无已验证的定向动态详情接口，本轮没有凭空新增私有 RPC。云端真正的处理延迟无法由缩短轮询消除，不承诺固定完成秒数。

## 可观测性

每条新核验记录配对确认时间、开始核验时间、核验次数、最近查询耗时、下次尝试及完成时间。耗时包含等待 Python 队列和网络响应，不等同于纯云端处理耗时；旧记录没有的历史时间不补造。全局脱敏诊断增加查询次数汇总及最近查询耗时最大值，保持不输出凭据、原名、哈希、云端标识或签名地址。

## 验收重点

自动测试覆盖增量保留未变更项目、分页、删除、失败证据失效及完整同步恢复、缓存共享；原生测试覆盖蓝色证据条件、不同云端标识/缺失配对的拒绝、持久化、独立调度名额、短退避与清理资格，以及原生蓝色行截图。

真机优先继续旧的原始配对待确认任务：观察蓝色对勾和核验进度，最终变绿后再计入已备份；确认等待期间创建普通上传，检查其可推进。使用同等网络、图库和新拍样本比较配对到完成的耗时，不只比较创建到完成。蓝色任务须始终不出现在清理候选。
