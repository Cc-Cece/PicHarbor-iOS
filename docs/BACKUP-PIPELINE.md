# 分阶段并发备份 · 0.2.25

## 行为与界面

默认使用自动模式，根据内置 iPhone 机型档位和当前设备情况调节。普通页面不显示设备型号、档位和内部调节信息。备份偏好提供“并发模式”和“高级配置”；自定义设置需输入范围内整数，支持恢复自动管理。设置按账号保存，即时影响后续调度，不改变已创建任务的画质、版本或 Live Photo 方式，不中断已启动上传。

备份卡片继续显示当前速度和剩余大小；首页及批次卡片补充“准备中／上传中／确认中”数量。任务流程按实际阶段显示，详细阶段和累计用时放在高级信息中。上传用时包括系统传输等待或暂停时间，其他阶段包含请求和代理准备耗时，不能作为纯网络 RTT 使用。

## 独立调度

| 阶段 | 工作 | 自定义范围 |
|---|---|---|
| 准备照片 | 稳定性检查、PhotoKit 导出、哈希、Live 封装 | 1–3 |
| 上传检查 | 内容查重、上传授权 | 1–4 |
| 文件上传 | URLSession 文件传输 | 1–12 |
| 保存与配对 | 响应解析、提交、Live Photo 联合或分步配对 | 1–4 |
| 云端确认 | 查询保存、配对结果及可选严格动态检查 | 1–4 |
| 缓存上限 | 尚未上传资源的预备字节预算 | 128–8192 MB |

云端等待使用持久化重试时间；等待期间不占工作名额。上传通道不再等待其他任务的哈希、提交、配对或严格动态确认。队列优先接续已准备好的上传和提交，再补充预备资源；已准备授权的数量也有上限，避免过早获取大量短期授权。授权等待超过三分钟会重新查询准备，未持久化签名地址。

每个逻辑资产一次传输一个资源，Live Photo 的照片与视频仍按原协议交接；多个逻辑资产可以并行。确认阶段仍可执行必要的协议查询、源文件复核和相簿同步，不占上传名额。不承诺所有时刻都能达到并发上限或持续占满网络。

## 自动档位与资源保护

- 已知 iPhone 15 Pro、16 系列且实际内存至少约 8 GB：基准为准备 2、检查 3、上传 6、提交 2、确认 2、缓存 768 MB。
- 已知较早的 6 GB 机型：1／2／4／2／1、512 MB；其他及未知机型保守采用 1／2／2–3／1／1、256 MB。未知机型不会因内存大而直接使用最高档。
- 低电量模式、严重发热、可用内存不足时降低新工作数量；内存警告、极低可用内存、严重发热或磁盘不足会暂缓新增准备并进一步降低上传数量。设备状况约每十秒刷新，温度、电源及内存警告也会触发刷新。
- 自定义模式也保留上述保护。系统调度、网络、代理和服务端限制仍可能降低实际并发；12 是应用允许输入的上限，不是 iOS 硬件保证。
- 缓存按流式写入计数，满时等待；一个超出预算的大资产允许在空缓存时单独推进，避免死锁。缓存上限不等于全部暂存目录上限：已上传待确认原件、封装副本及系统上传暂存仍可能占用空间。保留磁盘检查和启动后的引用核对，不批量清空仍在使用的暂存文件。

## 一致性与 Python 边界

SQLite 保存阶段、资源清单、系统传输 ID、上传响应和提交屏障。重启时从耐久检查点推导下一阶段；不依赖内存中的工作名额或签名地址。暂停、取消、切换账号后不会因排队中的工作再次启动而覆盖暂停意图。

协议调用使用独立 API 与可复用上下文，账号及代理隔离；每个上下文同时只被一个请求占用。Bearer 更新短暂串行，登录、退出和旧版数据库操作有独占屏障，等待在途协议请求结束后才更换身份。原始 gpmc 快照保持不变。Python GIL 仍限制解释器计算并行，网络 I/O 可重叠；Swift 导出和文件上传独立运行。

普通照片仍查重；Live Photo 仍要求照片哈希和视频哈希查询指向同一云端项目。提交结果不明时保留提交屏障，后续查询，不自动重传。严格动态检查默认关闭，配置和原有判断不放宽。本机释放空间继续交由 Google 相册。

## 验证与真机检查

新增原生测试覆盖万级队列的单次遍历、有界选择、独立名额、缓存背压、超大单资产、普通及两种原始配对的恢复阶段、提交屏障、配置范围与资源压力。新增 Python 测试验证请求真实重叠、代理隔离、跨线程上下文复用、异常释放和退出屏障。测试均使用合成数据，不访问用户账号。

需安装后验证：普通照片／视频／Live 混合队列是否持续推进，严格确认等待时其他上传是否继续；暂停与重启后接续，账号切换及代理切换；大于缓存的视频、低磁盘和低电量模式；自定义参数及恢复自动。万级队列的核心测试不代替 iPhone UI 帧率和实测吞吐验收。

完整 iOS app host 的模拟器测试此前存在启动中止限制；独立 Apple 原生核心测试通过不能表述为整个 UI 或真实 Python iOS 并发链路已完成真机验收。
