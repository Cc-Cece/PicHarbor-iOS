## A：免费自签与运行环境

1. 从成功的构建任务下载 unsigned IPA，记录构建链接、提交号、安装工具及其版本、iPhone 型号与 iOS 版本。
2. 使用 Sideloadly 或 AltStore Classic 重签，确认工具能签署全部嵌套 framework。按提示信任配置并启用开发者模式（如需要）。
3. 冷启动应用，确认“Python 已启动”，显示 Python 3.13、OpenSSL 和 SQLite 版本。
4. 导出诊断，记录 bundle_bytes；另行记录系统设置显示的 App 大小和数据大小。IPA 压缩体积、包内文件字节数与实际磁盘占用分开记录。
5. 若失败，记录发生在重签、安装、启动还是运行环境检查；收集工具错误代码、系统崩溃报告和应用诊断。不要附带 Google Cookie、auth_data 或完整 HTTP 响应。

通过标准：免费重签后的真机能够稳定启动并导入 gpmc，原生 TLS、哈希和 SQLite 模块可用。云端编译成功本身不满足此项。

## B：认证与单张照片闭环

1. 点击“登录 Google”，在 Google 页面完成认证。记录是否被拒绝、是否要求额外验证；不要采集密码或 Cookie。
2. 如网页登录被服务端拒绝，可用已有 gpmc 凭据继续验证协议，但需把网页登录标为未通过；不能据此声称完整认证通过。
3. 授予照片访问权限，选择一张普通静态照片。首次建议使用小体积样本，保持应用前台；默认采用计配额原画质参数，不承诺服务端实际配额。
4. 检查记录：已提交但哈希查询未确认时应为“待云端确认”；稍后使用“重新按内容核验”。不能仅凭提交返回就认定成功。
5. 在 Google Photos 独立检查照片是否可见，并下载原件比较 SHA-256；这一步用于样本完整性验证，应用内哈希存在查询本身不提供完整原件核验。
6. 再次选择同一张照片，记录应为“云端已存在 · 已查重”，不重复执行上传和提交。
7. 退出应用并重开，凭据可从 Keychain 恢复，连接同一账号后观察历史记录仍在。
8. 断网重试：显示失败或待确认，不能误报已确认。已提交但确认失败的记录能够单独重新核验。
9. 如有第二个账号，切换后只显示该账号记录；失败的账号切换不应继续使用旧账号操作。
10. 确认 UI 没有原件删除或云端删除入口，Live Photo 与视频不会被当作完整支持的样本。

通过标准：真实认证（或单独明确标记的已有凭据验证）、原件上传、独立云端确认、内容查重、重启持久化分别有证据；所有未知和失败状态保持可辨认。
