# 统一任务恢复 · 0.2.28（build 30）

## 操作与范围

- 任务详情：主动暂停显示“继续”，失败／需处理显示“重试”；云端确认保留“立即检查保存结果”。
- 活动或批次菜单：“继续暂停任务”仅恢复主动暂停的任务；“重试全部异常任务”处理当前筛选结果中的失败和需处理任务。
- 批量操作限定当前账号，排除已完成、已取消、已隐藏及主动暂停的任务；不会把等待自动查询的正常任务反复重置。
- 原有“重新准备此任务”普通入口已移除。修复不取消旧任务，不另建记录；账号、批次、任务 ID、资源 ID、版本及备份策略保持不变。

## 暂存文件恢复

“继续”和“重试”共用恢复规划。仍需本地文件的资源不存在，或原错误为文件缺失、变化、访问失败时，任务进入受并发和时间限制的准备阶段：

1. 先尝试在当前沙盒的同一任务目录内查找旧相对路径；拒绝跨任务和 `..` 路径。
2. 对文件计算 SHA-1、SHA-256 和大小，与原资源清单一致才复用。
3. 确实缺失或内容不匹配时，从 PhotoKit 按原任务策略导出到独立恢复目录；Motion Photo 重新封装。
4. 新导出资源必须同时匹配原角色、两种哈希和大小，才替换资源路径。保留上传回执、云端键、已提交／已确认状态和 Live Photo 配对记录。
5. 内容已变或原版本不能导出时提示从照片页面重新备份，不静默改变原任务，也不把旧云端证据授予新内容。失败导出清理本次恢复目录，不删除相册原件或其他暂存资源。

恢复标志持久化。恢复任务不会被旧资源的逻辑大小堵在预取缓存之外；新导出仍受流式缓存和磁盘容量约束。过期上传计划失效；必要时先解除旧传输 ID 再取消对应传输，迟到回执不能覆盖恢复进度。批量入队分段让出主线程，实际恢复复用现有准备、上传和查询并发限制。

已提交或已完整确认的普通资源，以及结果不明确的已提交配对，不因缺少本机暂存文件而重新导出或提交：仍查询云端。认证、权限、空间或原件访问问题需对应条件恢复；“重试”不绕过这些条件。手动重试开启新的有限自动重试预算，保留已有检查点。
