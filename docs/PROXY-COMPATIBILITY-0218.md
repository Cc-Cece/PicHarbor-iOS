# 代理兼容性修复 · 0.2.18（46）

## 已证实的原因

1. 部分订阅按 User-Agent 区分旧 Clash 与 Clash Meta。同一链接在 `Clash/PicHarbor` 下返回空节点列表，在 `clash.meta` 下返回 16 项。新版本使用后者，零节点也会明确报错。
2. Foundation 的 JSONSerialization 默认把 `/` 写为 `\/`。内置 SDK 将运行配置交给 YAML 解码器，拒绝这一合法 JSON 转义，报 `yaml: found unknown escape character`。AnyTLS 的 ALPN `http/1.1` 因此触发失败，与 AnyTLS 协议自身是否受支持不同。
3. 使用固定的 Apple SDK、虚拟节点和相同原生桥接，旧编码成功加载 SOCKS5、最小 AnyTLS 和带指纹 AnyTLS，但完整 ALPN AnyTLS 失败。禁用斜杠转义后，四组均成功。

## 修改

- 运行配置采用排序键及 withoutEscapingSlashes；JSON 输入直接由 Foundation 解析，避免再次经过不兼容的 YAML 转换。
- 部分节点无法启动时，逐项核对并导入能启动的节点；原始节点、失败项及脱敏原因保存在本机 Keychain，可在配置详情重新检查。全部失败时保留上一份可用配置，不将空配置标记为成功。
- 全部候选节点和过滤后的集合仍需通过整组启动、持久化提交；不能把“单节点能启动”误当作整份配置已完成应用。保存或启动失败沿用回退机制。
- 只在“流量／重置／到期”名称对应项与普通节点的完整连接参数完全相同时，将其分离为订阅信息。它们仍保留在原始内容中，不作为首选或备用节点。名称符合提示但参数独立的节点不会被误删。
- 错误只显示脱敏后的核心消息，不输出配置或令牌。启动成功仅代表配置可以加载，节点是否能连接 Google 仍由连接测试及真机备份验证。
