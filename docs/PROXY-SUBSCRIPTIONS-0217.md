# 配置与订阅管理 · 0.2.17

入口：设置 → 应用内代理（验证）→ 配置与订阅。

## 行为

- 支持从本地 Clash YAML/JSON 导入，或添加 HTTP/HTTPS 订阅。最多 20 份配置，每份最多 64 个节点；不使用导入文件中的系统 VPN、DNS、规则、控制接口，不支持 proxy-providers 或代理链。
- 一次使用一份配置。添加成功后使用新配置；更新已有的非当前配置不会切换当前连接。首选及备用节点按配置保存。全局与任务兜底策略沿用现有行为。
- 链接、节点及配置记录统一保存在本机 Keychain；编辑页显示普通链接，配置列表与诊断不显示地址。订阅手动更新，不定期后台刷新。
- 下载使用 Clash User-Agent，避免部分服务按通用客户端返回其他订阅格式；跳过本地缓存。网络下载在 UI actor 之外进行，避免逐字节读取阻塞界面。30 秒请求超时、45 秒总时限、4 MiB 上限。
- 依次经过下载、解析、节点校验、核心启动、保存和列表更新。只有全部成功才显示“更新成功”。记录成功时间、节点数和新增／修改／移除数量。修改比较节点内容，而非只比较名称。
- 新配置启动或 Keychain 保存失败时，不提交节点列表并恢复原来的运行配置；若旧核心也无法重新启动，会明确提示。更新失败记录保留，上次成功内容继续保留。
- 更新、切换前需暂停活动备份。下载期间若备份开始，导入会停止并提示先暂停备份。
- 删除需确认。移除当前配置会关闭应用内代理，不自动改用另一份配置；剩余配置仍保留。
- 从旧版升级时，已有节点自动成为“原有配置”。旧版没有保存订阅链接，因此需要重新添加链接才能管理后续更新。
